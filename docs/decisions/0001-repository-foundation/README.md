# 0001：采用研究项目工作区与 README 驱动展示

- **状态：** 已接受
- **日期：** 2026-08-30

## 背景

仓库将长期研究多个技术对象，各项目可能拥有不同语言、依赖和发布方式。同时，研究过程需要在 GitHub 中公开展示，并通过一个稳定入口被发现。

## 决策

- 根 README 作为项目索引和仓库首页的唯一内容源。
- projects 下每个目录代表一个可独立复现的研究项目。
- 不在根目录绑定统一应用框架或包管理器。
- 使用 Jekyll 将根 README 和各项目 README 包装为 GitHub Pages 页面。
- 使用项目模板统一最低证据要求，但允许项目添加自己的结构。

## 后果

新增不同技术栈的成本较低，根入口也不会依赖某个子项目的构建。代价是各项目可能需要维护不同工具链，跨项目自动化只能检查通用约定。

当项目数量显著增加、手工维护根索引成为负担时，可以引入元数据文件和索引生成脚本，但目前不提前增加这层复杂度。
