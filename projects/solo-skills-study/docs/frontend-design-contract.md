## Observable completion criteria

1. 首屏在 5 秒内说明 Solo Skills 的定位、规模、最重要价值和采用边界。
2. 页面列出锁定版本的全部 26 个技能，并能按知识型、脚本增强型、环境耦合型筛选且反馈数量。
3. 实现原理以可操作流程说明发现、加载、按需资源、执行和审批，不把 Skill 误称为后台服务或权限系统。
4. 使用场景同时说明适合与不适合的条件，并可在个人经营、研究团队、平台工程三个视角切换。
5. 案例实验室提供七个可切换案例；每个案例均展示触发语、输入来源、涉及 Skill、五阶段执行轨迹、阶段产物、外部依赖、副作用和最终门禁，并可逐步或一次运行完整流程。
6. 旗舰案例使用本研究项目真实 README、research-log、固定提交、测试结果和本地网页 URL，生成有证据边界的研究交付包；其余涉及个人或账号数据的案例明确标记为脱敏拟真 fixture。
7. 扩展案例覆盖信息提取、Skill 设计、浏览器/视频生产、内容发布、常驻情报和破坏性操作治理；结果包含 PASS、REVIEW、SETUP、DRY-RUN 或 HOLD 等不同门禁，而非全部伪装成成功。
8. 可扩展方向按优先级给出实施入口；“对我们的意义”连接本仓库的问题、实验、证据、Skill 和测试链路。
9. 1440px、768px、390px 三档视口无横向溢出、遮挡和不可达控件；明暗主题、案例键盘切换、reduced-motion 与无 JS 边界可用。
10. 页面结构测试、Solo Skills 结构契约测试和仓库验证被执行；结论明确说明交互演示没有证明真实模型质量或外部系统可靠性。
11. 七个案例各自提供可直接对 Agent 使用的自然语言调用示例，并明确列出用户材料、Skill 所贡献的规程、运行环境所贡献的工具/权限和可以观察到的效果。
12. 切换案例时上述使用说明和下方演示必须同步；用户无需先理解 `SKILL.md` 内部结构即可从目标进入完整运行。
13. `web-demo-video` 场景必须真正生成 1920×1080、32 秒、H.264/yuv420p、无音轨的 MP4；帧状态由 `frameIndex` 决定，交互目标来自真实 DOM rect，并通过真实 MouseEvent 操作同源页面。
14. 网页必须可直接播放真实视频并显示规格、生成时间、帧数和验证结果；视频案例终态只能在媒体文件、ffprobe 与代表帧目检全部通过后从 DRY RUN 升级为 READY。
15. 能力区首先显示 8 个面向结果的能力域，数量合计必须为 26；用户无需识别文件名即可理解内容媒体、写作风格、会议活动、消息触达、Agent 工程、计算路由、搜索证据和数据操作的覆盖范围。
16. 26 个 Skill 每个都有独立、具体、以结果为中心的一句话能力；例如 `web-demo-video` 明确表述为“把真实网页自动生成可复现的产品演示视频”，而不是只描述帧、事件或 FFmpeg 实现。
17. Solo Skills 在根研究索引、项目 README、Jekyll 入口和展厅首屏统一标识为 `R-007 / 第 7 个研究子项目`，并声明编号不随排序变化。
18. 根 README 的 R-007 行同时提供锁定上游源码、仓库内研究页、GitHub 项目源码和 GitHub Pages 在线 Web 四类入口，以及一句有证据边界的摘要。
19. 项目 README 的公开摘要在首屏即可回答能力、原理、演示、采用意义与未验证边界，并给出源库、研究源码、在线研究页、在线 Web 和真实 MP4 索引。
20. 只提交 R-007 项目及根 README 的对应索引变更；推送后 GitHub Actions 质量检查和 Pages 部署成功，线上 Web 在真实 Chromium 中通过加载、案例交互、视频元数据与 1440/390px 无溢出检查。

## Brief-led design direction

| 决策层 | 选择 | 可观察约束 | 验收标准 |
| --- | --- | --- | --- |
| Composition | 首屏结论 + Skill 栈示意，之后沿用户问题纵向推进，演示工作台位于中后段 | 每个 section 只回答一个主问题 | 首次扫描先理解定位，再自然进入能力与演示 |
| Focal hierarchy | 大标题和“现场 SOP 变成可加载能力”为主，26/49/9 数据为辅 | 数字不能压过核心判断 | 不依赖滚动即可回答“它是什么” |
| Typography | 系统中文黑体承担标题，宋体/衬线承担研究判断，等宽体承担技能名、提交和状态 | 正文行长约 40–72 个中文字符 | 桌面与手机无需放大阅读 |
| Palette | 纸张米白/墨黑双主题，安全橙为操作色，青绿色表示已验证，琥珀表示限制 | 每个状态同时提供文字或图形 | 两主题均保持清晰层级和可辨状态 |
| Material | 细线、编号、索引标签、打孔纸和操作日志；少量阴影，仅用于活动工作台 | 不使用玻璃拟态和装饰性大渐变 | 信息归属和交互区域一眼可见 |
| Depth | 仅粘性导航、选中步骤和演示输出具有层级 | 无装饰层遮挡正文 | 滚动、焦点与活动状态明确 |
| Density | 能力区高密度但可筛选；原理和演示区降低密度、逐步披露 | 单卡只保留一个结论和必要技能名 | 读者不需要来回跳转理解因果 |
| Motion | 只用于筛选、步骤切换、演示进度和主题，时间短且可关闭 | reduced-motion 下状态仍清晰 | 动画不延迟操作、不承担唯一信息 |

## Revision 2 · 真实案例实验室方向

| 决策 | 选择 | 原因 | 验收方式 |
| --- | --- | --- | --- |
| 旗舰案例 | `solo-skills-study` 研究交付包 | 当前项目具有可公开、可复查的真实输入和测试证据，不需要编造个人数据 | 页面显示真实文件名、固定 SHA、测试结果、URL、结论边界和生成产物 |
| 扩展案例 | 会议运营、工作坊设计、演示视频、内容发布、每日情报、安全清理 | 覆盖知识型、脚本增强、环境耦合以及低/中/高副作用 | 七个案例均能切换并完整运行，门禁结果不相同 |
| 数据真实性 | `LIVE PROJECT` 与 `SANITIZED FIXTURE` 双层 | 既满足真实证据，又避免账号、Token、客户和会议隐私 | 每个案例显示来源标签；fixture 不称为真实生产执行 |
| 信息架构 | 案例目录 → 运行契约 → 输入台 → 五阶段执行 → 产物/门禁 → 扩展接口 | 让用户看懂 Skill 不是单次回答，而是完整操作规程 | 桌面和移动端都能按同一顺序读完，不依赖横向表格 |
| 控制系统 | 七案例 roving tabs、五阶段 tabs、下一步、完整运行、重置 | 同时支持快速浏览和逐步理解 | 鼠标、方向键、Home/End、按钮路径均有浏览器证据 |
| 运行边界 | 前端确定性状态机；不发起网络请求，不执行真实删除或发布 | 避免把展示页变成不受控自动化入口 | 静态检查确认外部 API 调用为 0；页面明确展示外部动作保持关闭 |

## Revision 3 · 目标场景调用方向

| 决策 | 选择 | 原因 | 验收方式 |
| --- | --- | --- | --- |
| 入口语言 | 先展示“我要完成什么”，再展示 Skill 名称 | 普通使用者从任务出发，不会先从库目录选择文件 | 每个案例标题下首先出现目标与调用示例 |
| 调用示例 | 使用可以直接复制理解的自然语言请求，包含输入位置、输出、边界和审批要求 | 说明“如何使用”比仅显示触发词更接近真实协作 | 七个案例均有不同且具体的 prompt，切换后同步 |
| 职责拆分 | 明确列出用户提供、Skill 负责、环境负责、最终观察四栏 | 防止把 Skill 误认为自动提供 Token、工具和后台服务 | 浏览器可见四栏；内容随案例变化 |
| 演示衔接 | 使用说明和既有五阶段工作台在同一案例上下文内 | 用户可以先理解调用，再立即验证效果 | 场景选择后使用说明、输入和演示状态一起重置 |
| 视觉策略 | 保留研究档案视觉，用浅层“调用卡”提升可操作性，不增加新路由或弹窗 | 减少额外导航与认知负担 | 三档视口按四栏→两栏→单栏重排，无横向溢出 |

## Revision 4 · 真实网页视频交付方向

| 决策 | 选择 | 原因 | 验收方式 |
| --- | --- | --- | --- |
| 真实对象 | 当前运行中的 `http://127.0.0.1:4192/` 研究展厅 | 无需虚构客户数据，且页面、交互和结论都可复查 | 舞台同源嵌入真实页面并完成实际交互 |
| 输出 | 16:9、1920×1080、32 秒、20fps 源帧、H.264/yuv420p、无声 MP4 | 沿用案例中已经确认的产品演示规格 | `ffprobe` 精确检查尺寸、时长、编码、像素格式和音轨 |
| 时间轴 | `window.__tick(frameIndex)` 完整决定滚动、选择、阶段、字幕和结尾 | 避免录屏速度、机器性能和定时器导致结果漂移 | 渲染脚本按 0–639 帧调用并保存代表帧 |
| 交互证据 | iframe 与舞台同源；目标由 `getBoundingClientRect()` 测量并派发真实 `MouseEvent` | 证明是操作真实网页而不是拼接静态 mockup | 渲染结果和脚本同时保留，浏览器断言实际筛选/案例/阶段状态 |
| 页面整合 | 仅在视频案例显示原生 `<video>` 交付卡和验证元数据 | 用户能在同一案例直接看到实际效果 | 桌面、平板、手机均可播放/访问，其他六案例不出现媒体卡 |

## Revision 5 · 一句话能力索引方向

| 决策 | 选择 | 原因 | 验收方式 |
| --- | --- | --- | --- |
| 总览层 | 在 26 项清单前增加 8 个结果域摘要，数量合计 26 | 先回答“有哪些工作能力”，再解释 Skill 文件 | DOM 检查 8 个域和 4+3+5+5+4+2+2+1 数量 |
| 单项语言 | 所有描述统一为“动词 + 对象 + 可观察结果” | 技术实现不是用户购买或采用的能力 | 26 条均非空；关键代表项采用明确结果表达 |
| 技术信息 | Skill 名、知识/脚本/耦合类型和业务域继续保留 | 一句话简化不能抹掉依赖和成熟度边界 | 原有 26 项与 9/9/8 筛选计数不变 |
| 视觉层级 | 总览用紧凑编号卡；单项新增“一句话能力”微标签 | 让汇总和逐项解释形成两级阅读路径 | 1440/768/390 分别 4/2/1 栏，无横向溢出 |
