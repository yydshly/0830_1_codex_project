# ViMax 研究展厅 · 前端设计契约

## Contract

| 字段 | 决策 |
| --- | --- |
| Entry mode | Revision-led refinement，在现有研究展厅中把抽象场景说明升级为真实上游案例实验室 |
| Request revision | 2：用户要求“用真实的场景样例进行演示，对该库的能力进行说明理解” |
| Target user and context | 想在 5–10 分钟内判断 ViMax 能做什么、如何工作、是否值得采用或继续研究的技术人员、内容创作者与研究者 |
| Desired first impression | 像一份可信、克制、可操作的“AI 制片系统研究档案”，兼具电影制作感与代码证据感 |
| Visual ambition | Editorial |
| Experience architecture | Editorial Flow |
| Visual constraints | 单一主视觉焦点；高对比排版；不依赖外部字体；不用 WebGL；视频是增强层而非信息载体；支持明暗主题 |
| Information constraints | 必须覆盖能力、使用场景、实现方式、演示效果、可扩展方向；新增案例必须逐项区分官方文档输入、仓库默认脚本、上游 Benchmark fixture、源码推导产物和未实跑结果 |
| Operation constraints | 能力筛选、案例切换、案例阶段与镜头选择、流程节点、演示视频和主题均支持鼠标与键盘；无登录、无后端、无真实 API |
| State constraints | 默认展示猫狗 Idea2Video 案例；案例、阶段和镜头状态同步；Benchmark 只展示输入 fixture，不伪装成成片；JS 不可用时四个案例摘要和真实性边界仍可阅读 |
| Environment constraints | 项目内零依赖静态 HTML/CSS/JS；兼容 GitHub Pages；本地以 `python -m http.server` 运行 |
| Primary journey | 先理解“ViMax 是编排层而非基础模型” → 浏览能力 → 在真实案例实验室选择上游输入并检查阶段产物与镜头依赖 → 展开通用实现流程 → 查看无法映射到具体输入的官方样片 → 对照扩展机会与限制 |
| User-defined phases | 能力、真实场景样例、实现方式、演示效果、可扩展方向 |
| Required artifacts | 可运行网页、源码证据链接、上游演示素材入口、自动结构测试、桌面/平板/390px 截图、浏览器验收记录、交接说明 |
| Autonomy authorization | 用户明确要求用真实场景样例演示，视为对当前研究项目内可逆案例内容、交互与验收更新的直接授权 |
| User-decision boundary | 不调用付费模型、不部署公网、不复制大型第三方视频、不修改上游 ViMax 源码 |

## Observable completion criteria

1. 首屏明确说明 ViMax 的定位、三种输入模式和最终产物，不把它误称为视频基础模型。
2. 五个用户要求的主题都有独立、可导航的内容区，并能在窄屏自然重排。
3. 能力筛选、场景切换、流程节点、演示切换与主题按钮在真实浏览器中工作。
4. 页面同时展示上游真实演示与“效果不等于能力保证”的边界说明。
5. 代码证据固定到 commit `05a48943878312d88fe5a016c12a9654940ecc43`。
6. 1440px、768px、390px 视口无横向溢出、遮挡或不可达控件。
7. 明暗主题、键盘焦点、reduced-motion 和外部媒体失败回退可用。
8. 自动测试、项目能力验证和仓库结构验证均被执行；外部无关目录造成的阻断单独记录。
9. 真实案例实验室至少包含官方 README Idea 示例、仓库默认 Script 示例和两个上游 Benchmark fixture；每例能切换阶段与镜头，并显示来源、产物、能力解释和人工门禁。
10. 页面明确说明官方视频没有输入映射、Benchmark 没有配对成片或评分、Novel2Video 没有上游小说—成片配对案例。

## Brief-led design direction

| 决策层 | 选择 | 可观察约束 | 验收标准 |
| --- | --- | --- | --- |
| Composition | 首屏结论 + 制片流水线，之后按研究问题顺序纵向推进 | 每屏只保留一个主问题 | 初次扫描先看到定位和能力入口 |
| Focal hierarchy | 大标题和“一句话结论”为主，数据与版本为辅 | 版本徽标不得抢过标题 | 首屏 5 秒内能回答“它是什么” |
| Typography | 系统中文黑体作标题，宋体/衬线作研究引文，等宽体作证据与版本 | 正文行长约 45–75 个中文字符 | 桌面与手机均无需放大阅读 |
| Palette | 象牙白/炭黑双主题，朱砂为动作色，青绿为已实现，琥珀为待验证 | 状态不只依赖颜色，还带文字与图形 | 两主题信息层级一致、状态可区分 |
| Material | 细边框、编号、档案标签与时间线；不使用大面积玻璃拟态 | 卡片边界清晰但不堆叠阴影 | 内容归属一眼可见 |
| Depth | 仅导航、流程活动节点和媒体面板有层级 | 无遮挡正文的装饰层 | 滚动和弹层状态明确 |
| Density | 首屏精简，后续细节分块；证据与限制就近放置 | 单张卡片不超过一个核心结论 | 不需要来回跳转理解结论 |
| Motion | 仅筛选、节点切换、主题切换使用短过渡 | `prefers-reduced-motion` 下关闭非必要动画 | 动画不延迟操作或隐藏内容 |

## Revision 2 direction

| 决策层 | 保留 | 新增或调整 | 验收标准 |
| --- | --- | --- | --- |
| Composition | 纵向 Editorial Flow 与现有五段导航 | 将原“谁会用”面板替换为案例生产沙盘，不新增独立应用或后端 | 能力之后立即进入可操作案例，后续实现与演示顺序不变 |
| Focal hierarchy | 象牙白/炭黑、朱砂动作色与状态标签 | 案例标题、真实来源和真实性边界成为场景区第一扫描层 | 用户不点任何控件也能判断案例是否实跑 |
| Information | 证据靠近结论 | 每例统一呈现输入、阶段产物、8/14 镜头、说明能力与人工门禁 | 切换案例后四类信息同步且不混用来源 |
| Interaction | 语义按钮、roving tab、键盘焦点 | 增加案例、生产阶段和镜头三层选择；阶段/镜头采用按钮组 | 鼠标与键盘均能完成“选案例 → 选阶段 → 看镜头依据” |
| Responsive | 1100/820/560 既有断点 | 桌面三栏、平板双栏、手机单栏；镜头横向信息自然换行 | 1440、768、390px 无溢出或不可达控件 |
| Truth boundary | 官方视频与研究结论分离 | 为每例标记“官方文档输入 / 仓库脚本 / Benchmark fixture / 未配对成片” | 不出现“这些视频就是该案例结果”的暗示 |
