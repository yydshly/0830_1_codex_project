03 实现方式

它不是“一个 Agent”，
而是一条有状态的生产图

点击流程节点，查看每一层消费什么、产出什么，以及代码证据在哪里。

Router / Entry

先判断输入属于创意、剧本还是长篇小说

不同输入进入不同 Pipeline。Idea2Video 会先扩写；Script2Video 保留已有创作意图；Novel2Video 增加分块、检索和全局人物管理。

输入
idea / script / novel_text
输出
标准化叙事任务
查看 Pipeline 目录 ↗

LLM + RAG

层级拆分，局部规划时再找回全局上下文

小说被压缩成事件链；原文以 512 字符分块建立 FAISS 索引，每个事件召回相关段落并 rerank，再由 SceneExtractor 规划场景。

输入
原始文本、事件 process chain
输出
事件、场景、人物状态
查看 Novel2Video ↗

Agents / Structured artifacts

专职模块把剧本翻译成可生成的视觉规格

角色提取器维护外观描述，肖像生成器制作正 / 侧 / 背参考；StoryboardArtist 规划镜头，随后拆成首帧、末帧、动作和声音描述。

输入
场景剧本、风格与用户要求
输出
角色库、storyboard、shot descriptions
查看 Agents ↗

Camera dependency graph

让宽景成为中景和特写的视觉父节点

LLM 根据内容覆盖、景别和时间邻近关系建立无环相机树。子机位等待父镜头关键帧，必要时先生成转场视频，再抽取新视角。

输入
所有镜头的 visual_desc
输出
camera_tree.json、空间锚点
查看相机图实现 ↗

Image + Video providers

关键帧控制画面，外部视频模型负责让它动起来

图像生成器接收文本和角色 / 场景参考；视频生成器接收动作、声音描述及一到两张帧图。当前固定版本包含 4 个图像和 5 个视频适配器。

输入
prompt + reference_image_paths
输出
PNG 关键帧、逐镜头 MP4
查看生成器协议 ↗

MoviePy + Session state

复用已经完成的产物，把短镜头按剧本顺序拼接

每个阶段先检查目标文件是否存在；独立任务并行执行。最终使用 MoviePy 拼接 MP4。Agent runtime 另行记录会话、渲染状态和失效产物。

输入
逐镜头视频、场景顺序
输出
final_video.mp4、render status

观察框架 不只看“好不好看”

  1. 角色身份跨镜头脸部、发型、服装是否漂移？
  2. 场景空间反打、特写和新机位是否仍属于同一空间？
  3. 语义执行动作是否符合分镜，而非只保持画面漂亮？
  4. 镜头装配节奏、音频和切换是否像完整作品？
研究边界

精选 Demo 只能说明“系统可以产出这些样例”，不能给出成功率、平均质量或成本分布。

05 可扩展方向

最值得继续做的，
不是再加一个提示词

扩展应落在可测量的质量闭环、状态记忆、成本与生产控制上。

接通 VLM 质量闭环

把已有 BestImageSelector 接入主 Pipeline，生成多个候选、评分、低于阈值时重试，并记录失败原因和预算。

入口
agents/best_image_selector.py
价值
最接近论文、容易做消融

高价值

跨场景状态图

显式追踪服装、伤痕、道具、车辆、天气、时间与空间拓扑，让每个镜头在生成前先做状态一致性检查。

入口
global information + camera graph
价值

高价值

音频与时间线

增加 TTS、角色声纹、对白对齐、口型、音乐节拍、字幕和可编辑时间线，替代当前主要依赖视频模型原生音频与顺序拼接的方式。

基于薄协议接入 ComfyUI、Diffusers 或内部推理服务，同时处理鉴权、轮询、失败恢复和统一媒体格式。

研究判断 Adopt / Explore / Wait

值得研究，适合做样片；
还不该无验证地承诺成片。

Explore

如果目标是 Agentic 视频、长叙事、跨镜头一致性或内部工作台，ViMax 是很好的实验骨架。

Prototype

如果目标是短片提案、小说视觉化和前期预演，可以从 2 场景、8 镜头的小预算样例开始。

Wait

如果要求绝对身份一致、专业对白音频、低成本批量或完全离线，应先补齐关键模块。
