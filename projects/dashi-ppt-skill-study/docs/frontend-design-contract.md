## Observable completion criteria

1. 首屏在不滚动时明确说明它是“Agent 驱动的本地 PPT 生产线”，并同时显示 12 / 1020 / 8576 / 3+1 四个已静态核验指标。
2. 用户要求的六组内容均有独立锚点、清晰标题和证据/边界标识，导航可直接到达。
3. 能力区至少覆盖内容规划、版式匹配、四方案、浏览器编辑、媒体、校验和三种导出能力。
4. 原理区用可点击流程展示每层输入、处理、输出和关键证据，并明确宿主 Agent 与确定性引擎的分工。
5. 效果区可切换 HTML、PDF、PPTX，准确说明交互性、视觉保真和可编辑性差异。
6. 完整样例包含 9 个逻辑页、4 个方案入口、页面导航、密度/强调参数、可编辑标题和重置功能；页面内明确标注它是基于已核验机制的交互模拟，不是导出实测。
7. 受众区覆盖技术决策者、管理者、研究/咨询、产品设计、Agent 开发、教育培训和合规安全，并说明各自关心的价值与风险。
8. 使用场景、低适配场景和扩展方向提供优先级、价值、实现入口和验证标准，而不只列概念名词。
9. 1440px、768px、390px 无横向溢出、关键文字裁切、控件遮挡或不可达操作。
10. 明暗主题双向切换、键盘焦点、Tab/箭头操作和 `prefers-reduced-motion` 均有真实浏览器或计算样式证据。
11. 页面零外部运行依赖，GitHub Pages 路径有效；自动测试、项目能力测试和仓库结构验证均被执行，外部无关目录造成的验证阻断单独记录。
12. 证据账本至少列出 8 个源码锚点，可按已核验、上游自述、待验证筛选，并直接解释每条证据支持什么结论。
13. 替代方案比较至少覆盖人工 PowerPoint、在线 AI PPT、低层 PPTX 库和 Dashi，明确各自控制力、自动化、可编辑性、隐私与适用边界。
14. 采用评估器包含至少 5 个可操作维度；分数变化会产生“建议试点 / 有条件试点 / 暂不建议”之一，并给出可复制的决策摘要和恢复默认值。
15. 390px 提供可发现的移动导航；抽屉可通过按钮和 Escape 关闭，关闭后焦点回到触发按钮，且打开时页面主体不可误操作。
16. 样例工作台提供研究咨询、季度经营复盘、企业培训、项目方案路演四个实际使用场景，每个场景包含完整 9 页且内容结构明显不同。
17. 每个场景明确受众、交付目标、适用能力和“模拟数据”边界；切换场景后这些状态、页面目录、Deck、标题和故事弧同步更新。
18. 场景 tab 支持鼠标、触控、方向键、Home、End；切换后仍可使用页面导航、四视觉路线、密度、强调、标题编辑和重置。
19. 四个场景分别演示：证据型研究与建议、数据型经营复盘与行动、教学目标与测验、方案架构与阶段路演，避免只替换标题的伪场景化。
20. 首屏不再以“能生成 PPT”为主要卖点，必须直接比较通用单次生成与 Dashi 的 canonical content → 约束检索 → 3+1 → DOM 导出链路。
21. 机制实验台至少暴露条目数、数值数量和媒体需求三类输入；每次变化都可观察到候选版式的通过/拒绝状态及具体原因。
22. 机制实验台提供 3 个模板候选与 1 个 bespoke 方案，切换后布局结构明显变化，但内容指纹和事实块数量保持一致。
23. 机制实验台明确展示模板匹配、全稿分配和导出映射三个 Dashi 特性，并把交互计算标注为机制模拟，不伪装成真实上游运行。
24. 四场景样例的 4 个视觉按钮改为“模板候选 A/B/C + Agent 定制”，并显示当前页的内容映射、布局选择、复用控制和导出提示。
25. 新增差异化表面在 1440px、768px、390px、明暗主题、键盘与 reduced-motion 下保持完整、无横向溢出和状态矛盾。
26. 使用锁定提交、固定 `theme07`、固定 seed 和原创非敏感研究材料，生成至少 6 个逻辑页且每页包含 3 个模板方案与 1 个 bespoke 方案。
27. 真实实验必须保存可复现输入、goal、运行环境、布局分配、重复运行 diff、HTML/PDF/PPTX 产物与失败记录；不能只保存截图。
28. 对 3+1 的 required facts、关键数字和标题语义做自动检查，并在网页上给出实测分子/分母与异常项，而不是沿用模拟指纹。
29. 对导出 PPTX 至少记录逻辑页/导出页数、可编辑文字对象、媒体/形状或截图回退可观察统计，并明确这是本次样例，不外推为全库平均值。
30. 真实实验区可选择逻辑页和 4 个方案，展示对应真实截图、布局或 compositionFamily、内容一致性与导出边界；提供 PPTX、PDF、goal.json 下载入口。
31. 新增真实产物区域在 1440px、768px、390px、明暗主题和键盘路径下可用，且静态服务器与 GitHub Pages 中下载链接均有效。
32. 第二轮使用一个具有明确决策、受众和约束的完整业务场景，8 页依次覆盖现状、闭环、负荷图表、经济门槛、路线、治理和决策，不以孤立模板页冒充完整案例。
33. 页面可在 Dashi v4 与同输入直接编程基线间切换，并逐页展示两者真实 PowerPoint 渲染；路线切换后品牌忠实度、图表编辑性、对象与回退说明同步。
34. 页面明确展示请求品牌色、theme03 实际色和直接编程基线实际色，不能把“视觉方向相近”描述为“品牌精确复现”。
35. 效率比较只使用本机实际测得的 scaffold/render/export/build 时间；人工 PowerPoint、通用 AI 服务和模型 token 成本明确标为未测量。
36. 第二轮两份 8 页 PPTX 与 32 页对照稿均通过 PowerPoint 越界检查；直接编程基线逐页视觉检查并修复可见排版问题。
37. 新增对比器在 1440px、768px、390px 无横向溢出，鼠标和键盘均可完成路线与页面切换，所有下载链接返回 200。
38. 根 README、项目 README、项目页面与研究展厅统一显示 `R-003`，并明确它是仓库第 3 个研究子项目。
39. 根 README 的 R-003 行同时提供一段可独立理解的结论摘要、锁定上游源库链接、项目研究页和 GitHub Pages 在线 Web 链接。
40. 项目 README 首屏包含执行摘要、证据等级、两轮真实实验、四类模拟示例、源库索引、本地入口和 canonical 在线入口；实验矩阵不得继续把已完成实验标记为未执行。
41. Web 提供至少 6 个可扫描示例入口：REAL RUN 01、REAL RUN 02，以及研究咨询、经营复盘、企业培训、方案路演；每项显示真实/模拟证据标签、受众、主要能力和可到达锚点。
42. 发布文件范围只包含研究源码、原创输入、结构化报告、必要预览和被网页直接引用的下载产物；上游 checkout、缓存、重复渲染中间文件不进入 Git。
43. 本地发布候选在 1440、768、390px、明暗主题、键盘和 reduced-motion 下通过；发布前发现的 1440px 横向溢出必须归零。
44. 推送 `origin/main` 后，Repository checks 与 Deploy research site 均成功；canonical GitHub Pages URL、根站点 R-003 索引、示例切换和公开下载链接返回 200。

## Brief-led design direction

| 决策层 | 选择 | 可观察约束 | 验收标准 |
| --- | --- | --- | --- |
| Composition | 首屏“结论 + deck 机器”双栏，随后按能力→原理→效果→样例→受众/场景→扩展/边界纵向推进 | 每个章节只回答一个主问题 | 第一次扫描先看到定位和可操作样例入口 |
| Focal hierarchy | 大标题与一句话定位为主，指标为证据，按钮为行动 | 指标不能抢过定位；装饰不能覆盖正文 | 5 秒内回答“它是什么、谁在生成、产物是什么” |
| Typography | 系统无衬线负责标题和正文，等宽字体负责版本、数据和证据，少量中文衬线用于结论引语 | 正文行宽约 42–76 个中文字符 | 三个目标视口都无需缩放阅读 |
| Palette | 纸白/炭黑双主题；钴蓝动作、酸绿验证、珊瑚边界、灰色待验证 | 状态同时有文字/图形，不只依赖颜色 | 双主题均保持层级、焦点和状态差异 |
