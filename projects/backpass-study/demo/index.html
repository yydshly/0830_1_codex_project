00 / 一分钟理解

这不是自动写规则，
而是给规则建立反馈闭环。

今天的 Agent 会话会留下大量过程记录，但下一次会话通常不会从这些记录中学习。Backpass 将“真实发生过什么”变成项目指令的维护依据。

它是 证据约束的项目记忆优化器
它不是 模型微调、代码审查或 CI
01 / 能力

从会话仓库到可审查修改

七类 Agent 历史、两级模型、一个人工闸门。每个阶段都尽量把“模型说了算”缩到最小。

A1

发现并归属会话

读取 Claude、Codex、Pi、OpenCode、Grok、Cursor CLI、Hermes 的本地记录。

  • worktree
  • git remote
  • best-effort
A2

确定性压缩

保留人类与 Agent 消息，把工具调用压成一行，并限制长会话输入规模。

A3

单会话损失分析

区分规则带来的正向作用、伤害、未遵循、无关与尚未覆盖的缺口。

A4

跨会话证据折叠

新规则默认需要至少两个不同会话支持，避免一次偶发失败改写长期记忆。

A5

预算内提出修改

支持新增、重写、删除和抽取为 Skill；默认一次最多五项小步修改。

A6

人工审核与安全写入

只有 backpass apply 写入；写前重验版本、预算与组合，失败时回滚。

✓ 人拥有最终权重
02 / 实现原理

“梯度下降”是一套工程映射

真正确定性的部分是发现、采样、计数、diff 与写入门槛；损失解释和修改综合仍由 LLM 判断。

  1. 1
    Collect为当前仓库找到真实会话
  2. 2
    Distill去噪、截断并脱敏
  3. 3
    Calculate loss逐会话判断规则影响
  4. 4
    Aggregate折叠重复证据与缺口
  5. 5
    Propose & apply暂存编辑，人类选择落盘
机器学习隐喻实际对象
权重AGENTS.md + Skills
前向传播一次 Agent 会话
损失成功、违规、伤害、缺口
梯度跨会话定性证据
学习率单次修改上限
模型容量常驻 Token 预算
近期加权采样 weight = 2−age / halfLife

近期会话更容易被保留，旧会话仍有机会进入样本；每个会话的随机值由稳定哈希产生，重跑不会无故洗牌。

04 / 使用场景扩展地图

从仓库治理，扩展到可审查的工作方法

Backpass 的通用前提不是“有聊天记录”，而是有重复任务、可定位的结果信号、可写回的记忆表面，以及愿意审核修改的人。下面按落地距离区分当前能力和扩展想象。

01 / CURRENT 当前近似可用

会话天然属于 Git 仓库，经验可写回 AGENTS.md 或 Skill。

02 / ADJACENT 近邻扩展

仍围绕研发仓库，但需要接入测试、CI、发布或任务谱系等结果证据。

03 / DOMAIN 领域扩展

需要新的会话适配器、业务真值、权限治理和专用记忆载体。

采用门槛

先判断有没有真正的反馈闭环

成立条件
  • 任务重复相似任务足够多，能形成跨会话证据
  • 结果可观察测试、返工、采用结果或业务指标可作为真值
  • 记忆可写回存在规则、Skill、SOP 或 Runbook 等稳定载体
  • 人类可审核责任人能理解证据、拒绝建议并承担决策
停止信号
  • 没有客观结果只能从对话措辞猜测好坏，因果归因不可靠
  • 样本高度相关同一任务的重试被误当作独立支持证据
  • 数据不可合规处理脱敏、权限和保留策略不足以保护敏感内容
  • 无人承担审核机械门槛能查形式，不能替代领域责任人

06 / 可扩展方向

从“会读日志”走向“可证明有效”

最重要的扩展不是支持更多模型，而是让损失更客观、证据更独立、作用域更准确。

P0

结果驱动的损失

把测试、CI、用户返工、最终 diff 是否保留加入证据，不只让 LLM 阅读对话猜因果。

可信度
P0

旧/新记忆反事实回放

用同一组合成任务比较修改前后成功率、返工次数、Token 与工具调用。

可验证
P0

目录级项目记忆

让 projects/<name> 的局部经验留在局部，只有跨项目共性才提升到根规则。

最适合我们
P1

隐私与 Windows 基线

原始会话默认禁读、DLP 与本地模型模式；修复路径、假可执行文件和 symlink 测试。

可采用
P2

团队证据治理

通过 PR、Code Owners、规则有效期和效果看板共享派生证据，而不是共享原始会话。

可规模化
07 / 对我们的意义

它最像研究仓库的“方法论编译器”

价值 01

让研究规范从声明变成反馈系统

版本、许可证、research-log、根索引和验证命令，不再只靠人记得；重复遗漏会形成待审核证据。

价值 02

控制多技术栈规则膨胀

高频、安全关键规则留在根记忆，低频流程抽到 Skill，减少每次会话都付费的常驻 Token。

价值 03

提供一个可研究的元课题

我们可以测量规则修改前后的返工率，而不是停在“这个提示词看起来更好”的主观判断。
