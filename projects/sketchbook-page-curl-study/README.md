# R-001 · Sketchbook 柔性翻页与可变表面研究

> 以 MengTo/sketchbook 的 CSS 3D 条带链为可验证起点，从柔性翻页扩展到 18 种书型、12 种非书可变表面、8 个内容上下文与 5 种视觉材质，并用六轴 36 方向图谱回答能力、原理、场景、扩展方向和采用意义。

## 公开摘要

MengTo/sketchbook 最值得研究的不是圆形放大镜，而是将一张翻页离散为嵌套 CSS 3D 条带，让统一进度沿页面传播并形成连续曲率。Revision 7 前的严格盘点是：用户列举的 10 种创意书型已有 10/10 独立 renderer，但 8 种非书形态按“脱离书本拓扑的具名实现”计为 0/8。本轮在不复制上游源码和素材的前提下补齐这 8 项，并增加卷轴海报、径向样本扇、撕取优惠券和数据丝带；现在内容、表面和材质成为三个可独立选择的维度。六轴 36 方向图谱继续用 `LIVE`、`REMIX` 与 `HORIZON` 区分真实实作、邻近模拟和远期概念。

## 一句话结论

Sketchbook 的核心不是放大镜，也不只是一种书，而是把刚性平面切成连续条带，通过输入让曲率传播并在正反两面之间完成空间过渡；书本只是这一能力的一种锚点与拓扑包装。

## 研究问题

1. 上游实际提供了哪些能力，哪些只是视觉内容？
2. 18 条嵌套竖条为何比单个 `rotateY` 页面更像柔性纸张？
3. 该实现适合哪些产品，何时不值得承担 DOM 与调试成本？
4. 我们既有的刚性翻页研究能复用什么，又缺少什么？
5. 如何在不复制无许可证素材和源码的前提下，用独立实验验证机制？
6. 除普通对页书之外，创意书型能否作为独立维度，在同一网页舞台中直接操作和比较？
7. 如何把更多创意方向组织成可筛选、可追溯、可回到实作验证的地图，同时不把概念路线冒充完成品？

## 初步证据

- 上游是零构建的单页实现：一个 `index.html` 搭配九组展开页 PNG 与本地字体。
- 柔性页使用 18 个嵌套竖条，每条含正反面，并通过 `backface-visibility` 与逐段旋转构造曲面。
- 统一进度 `t∈[0,1]` 映射基础翻转角；正弦隆起项控制中段曲率，逐条分摊角度增量。
- 释放时同时考虑进度阈值与拖动速度，决定提交到下一页或弹回当前页。
- 圆形放大镜克隆当前书本 DOM，再以独立坐标和缩放显示；它是增强层，不是翻页算法的组成部分。
- README 对图片来源写作 GPT Image 2，而源码注释写作 Higgsfield；当前证据只能确认表述不一致，不能推断真实生成来源。

## 既有翻页研究的关系

我们以前确实实现的是翻页，不是放大镜。`matthewyu-effect-lab` 的临时页是一个刚性平面，主要研究书脊起转、正反面隐藏、分段时间和输入阈值；本项目把它保留为对照组。Sketchbook 新增的关键知识是“沿页宽传播的分布式曲率”，并附带独立的放大镜与指针视差。

## 对你的意义

- 你现在拥有的不只是一个“翻页特效”，而是一套可比较的可变表面语法：连续弯曲、剥离、铰链、拉幕、换面、展开、显影、释放和循环都能复用为产品行为。
- 做方案时可以先问“内容关系需要哪一种力和哪一种显露方式”，再选 renderer，而不是先画一本书再寻找用途。
- 18 个书型与 12 个非书表面可以直接作为原型起点；书只是拓扑之一。36 方向图谱适合做概念发散、产品工作坊和技术预研；12 个组合场景展示怎样把两个或三个机制组合成完整任务。
- 成熟度标签能控制研发风险：LIVE 可进入体验验证，REMIX 先验证交互假设，HORIZON 必须在获得硬件、数据或多人基础设施后再立项。
- 对既有翻页项目而言，最直接的工程收益是统一的 `progress / step / turn` 状态模型；最重要的设计收益是把“书的物理结构”提升为信息架构，而不只是转场动画。
- 对商品揭示、展览开场、路线导览、数据叙事、配置器和拆解说明而言，可以先选内容关系、锚点、切片、形变和释放，再决定是否仍需要“书”的外观。

## 当前结论

- **已由源码支持：** 核心能力是 CSS 3D 条带链、连续拖拽、速度/进度提交、放大镜、视差、键盘/触控与 reduced-motion。
- **已由既有基线支持：** 单平面翻页更简单、更稳定，适合普通阅读流；柔性条带更适合视觉叙事和作品展示。
- **已由 Revision 6 独立实现支持：** 场景与书型在概念上回答两个不同问题，但当时的网页仍以互斥面板展示，不能宣称已经实现自由组合。场景改变“书里是什么”，书型改变“页面如何连接、展开、遮挡、成像或循环”。
- **已由 Revision 6 图谱支持：** 创意不能只按视觉外观分类。六条更有用的判断轴是连接拓扑、施力机构、显影材料、叙事状态、身体环境与数据生成；用成熟度标签把“可运行原型”“可信模拟”和“远期系统”分开，能让研究结论继续可验证。
- **已由 Revision 7 表面系统支持：** 内容、几何与材质可以成为独立状态。12 个非书 renderer 已补齐原列举的 8 种形态并增加 4 种；共享条带引擎证明角点剥离、镜像拉幕和边缘卷起可以复用同一“切片—曲率—正反面—光照”能力。
- **待实验：** 不同条带数的实际帧时、移动设备热/功耗、复杂页面内容的切片一致性与辅助技术体验。

## 结果与证据

- 纯函数、CSS 单位、质量预算、双入口、扩展场景、18 种书型结构、12 种非书表面、五材质、创意图谱数据与公开索引共 35 项测试通过：`node --test projects/sketchbook-page-curl-study/tests/*.test.mjs`。
- Revision 7 逐一驱动 12 种表面，直属结构计数为 14 条标签、8 个地图面、20 条幕布、18 片百叶、7 个事件、8 个样本、6 个盒面、6 层 portal、12 条卷带、10 个扇片、16 个穿孔和 8 个数据节点；全部在进度变化时产生可检查的 transform/state。
- 五种材质在 12 个表面上得到 `12 × 5` 组互不相同的舞台截图哈希；这证明每个表面都消费了可见材质状态，不等同于证明真实材料物理。
- 深链 `progress=.43` 的数据丝带在刷新前后均保持 step=`3`（节点 4/8）；标签左上、幕布向外、盒网向下、portal/卷轴向上与票券向右的定向拖动均产生正向进度，票券可进入 `detached=1`。
- Revision 7 在 1440、768、390 三档均 `scrollWidth===clientWidth`；reduced-motion 把过渡时长降至 `1e-06s`，fallback 保留静态终态并禁用动态 action/range。标签深链加载 8 个本地资源、0 个外部资源、478 个 DOM 节点，navigation 约 235ms，console/page/request errors=[]。

## 已知限制

- 当前实验用 CSS 3D 和原创 SVG 页稿验证机制，不是上游水彩视觉的像素级复刻。
- 八套页稿与四种场景专属交互均为本项目原创独立实现，不是从上游复制的产品功能或素材。
- 十八种创意书型、六轴 36 方向与 12 个组合场景都是对“书籍结构作为界面”的独立扩展研究，不是 MengTo/sketchbook 已提供能力的归因；其文字、SVG、DOM、样式与控制逻辑均为本项目原创。
- 十二种非书表面与五种材质预设同样是本项目独立扩展，不是 MengTo/sketchbook 原生能力；织物不含连续布料或自碰撞，金属不含 PBR/塑性形变，portal 不代表 WebGL 场景连续穿越。
- REMIX 只表示当前架构能够可信模拟关键机制，HORIZON 则明确依赖摄像头、传感器、多人系统、实时服务或 WebGL；两者都不应被当作已完成产品。
- 书型 fallback 展示静态终态并禁用动态控制；`prefers-reduced-motion` 下不会自动播放翻动画册，而是由用户逐帧推进。此降级设计不等同于真实辅助技术或物理触控验收。
- 浏览器工具的 iPhone 15 预设仍报告 `maxTouchPoints=0`，因此真实触屏抓取、发热和功耗仍需实机复验。
- 条带切片适合固定比例的视觉页；任意可选择文本、表单或复杂嵌套 DOM 需要单独的内容快照/无障碍方案。
- 本机 Core Web Vitals 只覆盖加载，不替代翻页期间的持续帧时、内存与低端设备测试。

## 后续问题

1. 能否把既有刚性控制器与条带渲染器收敛成统一 `PageTurnController → Renderer` 接口？
2. 如何根据实时帧时在 8/12/18/24 条带间自适应，而不在拖动中跳变？
3. 真实 iOS/Android 上 Pointer capture、滚动竞争、热量和电量表现如何？
4. 动态 HTML 内容应使用 DOM 切片、SVG 快照、Canvas 纹理还是 WebGL 网格？
5. 十八种书型应继续共用 DOM/CSS 状态机，还是抽象为可插拔的 `BookFormRenderer` 合约并允许 WebGL/物理模拟后端？
6. 哪些 REMIX 方向值得升级为第 19 个真实 renderer，哪些应保持为内容或材料层而不是新书型？
7. 如何把 `content → surface → material → interaction` 收敛成可插拔 renderer 合约，并让 CSS 3D 与 WebGL/物理后端共享同一状态协议？
8. 哪些场景真正需要任意方向网格、自碰撞与布料求解，哪些使用固定切片的 CSS 近似已经足够？
