能力地图 WHAT IT CAN DO

它把“看一页”变成
一段可操纵的物理叙事。

上游的能力可以拆成三层：翻页本体、交互控制和氛围增强。只有第一层决定它是不是“柔性纸张”。

上游事实

01 / CORE

柔性页面曲率

翻动页由 18 条嵌套竖条组成。每条都继承前一条的位置，再增加一小段旋转，于是整页不再像门板绕轴转动。

  • 正反面可见性
  • 逐条明暗
  • 双向翻页
上游事实

02 / INPUT

连续拖拽与甩页

水平位移直接映射进度；释放时把翻过多少与末端速度结合，决定完成还是回弹。

上游事实

03 / OPTICS

纸张光照反馈

每个条带用当前切线方向估算明暗与高光，让曲率不仅改变轮廓，也改变材质读感。

独立增强

04 / LOUPE

圆形放大镜

复制当前书本，围绕镜下坐标放大并裁成圆形。它位于书本倾斜层之外，因此可以像桌上的真实物件一样保持独立。

体验增强

05 / SPACE

指针视差与缩放

整本书随指针轻微俯仰，工具栏提供缩放；翻页时暂时稳定视角，避免多个自由度互相抢夺。

可访问意图

06 / FALLBACK

多输入与减弱动效

方向键、Pointer、触控回退与 prefers-reduced-motion 让同一内容不依赖单一手势或长动画。

机制拆解 HOW IT WORKS

一条公式，
分成十八小步。

把翻页进度记作 t。基础翻角决定页面从右到左走了多远，正弦隆起只在中段出现，保证起点和终点都重新摊平。

θ = πt

β = 0.60 sin(πt)

δ = 2β / N

  1. 01

    先把整页切成 N 条

    每条只展示原图的一段，并拥有 front/back 两面。背景偏移在开始翻页时计算一次，拖动过程中不再改切片。

  2. 02

    让条带首尾嵌套

    第 i+1 条相对第 i 条平移一个条宽，再旋转一个小角度。父级变换会沿 DOM 链累积，形成连续切线。

    012…N
  3. 03

    用隆起控制“软”

    β 在半翻时最大，两端为零。刚性模式相当于始终令 β = 0：所有点共享一个法线。

    rigidcurved
  4. 04

    把切线转成明暗

    每条带用法线与光线夹角近似纸面受光，叠加边缘阴影与高光。形状和材质一起变化，纸感才成立。

从原型回到工程路线

验证价值之后，再决定是否承担完整实现成本。

  1. 现在 · 工程化

    Renderer / Controller 解耦

    保留统一进度、阈值和页索引；将 rigid、strip-chain、未来 WebGL 作为可替换渲染器。

    PageTurnController → Renderer
    高价值 / 中成本
  2. 现在 · 内容化

    内容适配器与动态切片

    从固定 PNG 扩展到图片、SVG、文章快照或 Canvas 纹理，同时处理双页裁切与响应式比例。

    SpreadSource → FaceSlices
    高价值 / 高成本
  3. 下一步 · 性能

    自适应条带预算

    依据页面尺寸、设备能力和帧时动态选择 8–24 条带；拖动时降低阴影复杂度，结算后恢复。

    quality = budget(frameTime)
    高价值 / 中成本
  4. 下一步 · 交互

    角点抓取与二维纸张模型

    当前只有水平进度。加入抓取高度、角点约束和纸角路径，可表达局部折角而非整宽均匀弯曲。

    t → {x, y, curl}
    中价值 / 高成本
  5. 探索 · 渲染

    WebGL 网格与真实光照

    把 DOM 条带换成细分网格、法线和纸张着色器，适合更自由的弯曲与稳定光照；语义内容必须另留可读层。

    DOM strips → mesh vertices
    条件价值 / 高成本
  6. 探索 · 产品化

    编辑器、埋点与无障碍视图

    提供页稿检查、拖拽热区、跳页目录、阅读顺序和降级页面，让效果进入真实生产流程。

    authoring + telemetry + fallback
    高价值 / 高成本

对我们的意义 SO WHAT

旧项目给我们“可用翻页”，
这个库给我们“质量旋钮”。

保留

控制器与输入模型

页索引、方向键、触控阈值、提交/回退和 reduced-motion 都能继续复用，不需要重写产品逻辑。

新增

可替换的柔性渲染器

在需要主视觉的页面启用条带链；在内容密集、低性能或辅助模式中回到刚性页或普通文档流。

纠偏

放大镜不是核心差异

它可以单独组合进地图、画廊和细节检查器，也可以完全移除；删掉它不会改变翻页几何。

机会

形成统一 PageTurn API

下一阶段最有价值的不是继续临摹视觉，而是把控制器、渲染器、内容源和质量策略变成清晰接口。
